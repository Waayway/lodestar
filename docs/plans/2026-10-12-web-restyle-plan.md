# Web restyle and restructure plan (2026-10-12)

The dashboard gets its own look, the "Nautical chart", defined in a style guide
and built from small components, and `web/src` is reorganised by concern.

Reference mockup (approved by the user): `docs/plans/2026-10-12-web-restyle-mockup.html`
(a Design-canvas `.dc.html`; read its `<style>` blocks: stylesheet 1 = shared
structure, stylesheet 3 = Nautical chart (light), stylesheet 5 = Nautical chart,
night watch (dark, layered on 3), and its markup for layout and copy).
Stylesheets 2 and 4 (Night sky, Ops console) were rejected; ignore them.

## Look

- Light theme = Nautical chart; dark theme = Nautical chart night watch. Tokens
  exactly as in the mockup (`--bg`, `--panel`, `--chip`, `--fg`, `--muted`,
  `--line`, `--line-soft`, `--accent(-soft/-line)`, `--ok/warn/bad/info(-soft)`,
  `--nix`, `--stable(-line)`, `--unstable(-line)`, `--btn-*`, `--log-*`, `--r`,
  `--r-sm`, fonts) as CSS custom properties, mapped into Tailwind v4 `@theme` so
  components use utilities (`bg-panel`, `text-muted`, `border-line`, …) rather
  than raw hex.
- Fonts: IBM Plex Sans (body), IBM Plex Serif (display, wordmark italic),
  IBM Plex Mono (hashes, logs). Bundled via `@fontsource/*` (no runtime CDN).
- Chart grid background (32 px), round logo mark with the four-point star,
  serif italic wordmark, section headings with a rule after them, dotted row
  separators, solid promote card.
- Theme follows `prefers-color-scheme`; a small toggle in the header
  (system / light / dark) overrides it, remembered in `localStorage` (wrapped
  in try/catch, works without it). Implement with a `data-theme` attribute on
  `<html>` and both `@media (prefers-color-scheme: dark)` and
  `[data-theme=dark]` selectors so the toggle wins both ways.
- Icons: Lucide (`lucide-react` through preact/compat) for UI icons; OS/brand
  icons from Simple Icons (`simple-icons` package: `siNixos`, `siApple`; use
  their path data in a small `<BrandIcon>` component, not the whole package at
  runtime — import the named exports so the bundler tree-shakes). NixOS in
  `--nix`, Apple in `currentColor`. No emoji.
- Motion: only the building spinner; respect `prefers-reduced-motion`.
- Accessibility: real buttons, `aria-label` on icon-only buttons, text contrast
  ≥ 4.5:1 in both themes (check the muted and state colours on panel/bg).

## Structure

```
web/
  index.html
  src/
    main.tsx                 render(<App/>) only
    App.tsx                  providers only: ThemeProvider, TooltipProvider,
                             Toaster, ConnectionProvider; renders <DashboardPage/>
    pages/
      DashboardPage.tsx      composes sections; no data logic
    connection/
      client.ts              HTTP API (X-Lodestar header, ApiError, 403 detection)
      feed.ts                WebSocket feed with reconnect/backoff, 403 stop
      ConnectionProvider.tsx state (snapshot, channels, promote, live logs) + context
      hooks.ts               useFleet(), useHost(name), useApplyLog(host, id),
                             useActions() (apply, applyChannel, promote, fetchLog)
    lib/
      format.ts              labels (shortRev, behindLabel, onlineLabel, applyBadge, skip reasons)
      applyLog.ts            byte-offset merge (LogChunk.next) + refetch decisions
      time.ts                relative time, durations, useNow()
      theme.ts               theme state + persistence
      cn.ts                  class merge helper
    components/
      ui/                    shadcn primitives restyled with the tokens
                             (button, badge, card, dialog, sheet, table, tooltip, sonner)
      brand/                 Logo (star mark + wordmark), ThemeToggle
      fleet/                 StatTile, ChannelCard, PromoteCard, HostTable, HostRow,
                             OsIcon, StatusBadge, OnlineState, ChannelPill,
                             CommitHash, BehindCount, ApplyLogSheet, AuditList, LivePill
      layout/                PageHeader, Section (heading with rule), EmptyState, ErrorState
    icons/
      index.ts               the Lucide icons used, re-exported under Lodestar
                             names (Apply, Promote, Log, Applied, Building, …)
      BrandIcon.tsx          NixOS / Apple from simple-icons path data
    styles/
      tokens.css             light + dark custom properties
      base.css               Tailwind import, @theme mapping, fonts, chart grid
    bindings/                generated by ts-rs (unchanged)
  tests/                     by behaviour, not by file:
    formatting.test.ts       labels and copy
    log-streaming.test.ts    merge, offsets, refetch, gaps
    connection.test.ts       client errors, feed reconnect/backoff, 403 stop
    components.test.tsx      StatusBadge/HostRow/ChannelCard render the right
                             state, label and icon for each state (preact
                             testing library or plain render to string)
```

Rules:
- `App.tsx` contains no state or logic beyond composing providers and the page.
- Components get typed props (from `bindings/` types); data access only via
  `connection/hooks`. No component calls `fetch` or opens a socket.
- Copy stays as in the current app (it was reviewed); new UI copy is plain.
- Keep the existing behaviour and the fixes (log merge by `next`, refetch on
  snapshot / apply end, one log request at a time, 403 state, promote dialog
  pins the commit it showed, candidate refresh after promote).
- Update the Vite/tsconfig/vitest config for the new paths (`@/` alias stays;
  tests import via `@/…`).

## Style guide

`docs/style-guide.md`: purpose and character (a navigator's chart; calm,
precise); colour tokens for both themes with their role and contrast notes;
typography scale (sizes/weights for wordmark, section headings, body, labels,
mono); spacing and radii; the chart grid; state system (applied / building /
skipped / failed / off / agent not answering / behind / dirty — colour, icon,
copy for each); icons (Lucide set with the Lodestar names, brand icons and their
colours); every component in `components/` with its props, states and when to
use it; layout rules (sections, table on narrow screens scrolls in its box,
cards stack below 900 px); motion and accessibility rules; do and don't.
